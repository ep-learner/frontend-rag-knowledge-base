# 来源笔记整理 Skill

## 用途

将 `content/active/03-source-notes/_pending/` 目录下的待整理原始笔记，按照对应的模板格式，由 Agent 智能整理为标准化笔记，然后移动到 `content/active/03-source-notes/` 下对应的分类目录中。

**触发场景**：
- 用户说「整理笔记」「处理待整理」「pending 里的笔记整理一下」
- 用户提到「把这些笔记入库」「归置一下来源笔记」
- 用户从笔记整理工作台保存了笔记后，说「用 skill 整理一下」

---

## 第一步：列出待整理笔记

读取 `content/active/03-source-notes/_pending/` 目录下所有 `.md` 文件，列给用户选择：

```
content/active/03-source-notes/_pending/
  ├── 2026-07-13_React性能优化技巧.md
  ├── 2026-07-12_B站视频-Vite配置详解.md
  └── ...
```

每条显示：
- 文件名
- 标题（从 frontmatter 或正文第一行提取）
- 来源链接（如果有）
- 模板（如果指定了）
- 创建时间

让用户选择要整理哪一条，或者说「全部整理」。

---

## 第二步：读取笔记内容

对选中的每条笔记：
1. 读取文件完整内容
2. 解析 frontmatter（title / source / template / date）
3. 提取正文内容（去掉 frontmatter 之后的部分）

---

## 第三步：选择模板

**优先使用笔记中指定的 `template` 字段**，如果没有指定，则：
- 根据内容自动判断类型（技术笔记 / 视频沉淀 / 工具经验 / 其他）
- 询问用户选择哪个模板

可用模板参考 `client/public/note-templates/` 目录下的模板文件，也可以直接读取对应文件获取完整模板内容。

常用模板：
1. **前端技术笔记（通用）** - `frontend-tech-note.md`
2. **视频知识点沉淀** - `video-knowledge-sediment.md`
3. **工具使用经验** - `tool-experience-note.md`

---

## 第四步：智能整理内容

**核心步骤**：由你（Agent）根据模板结构，对原始素材进行整理。

要求：
1. **保持事实准确**：不编造、不歪曲原始内容，不懂的就标注「待确认」
2. **结构化输出**：严格按照模板的章节结构来组织内容
3. **保留原始素材**：在笔记末尾附上「原始素材摘录」章节，把原始内容放进去备查
4. **智能分类**：根据内容判断应该放到哪个分类目录下（如 `工程化/`、`React/`、`工具效率/` 等）
5. **价值判断**：给笔记打一个 1-10 分的价值分，判断是否值得长期留存

占位符替换规则：
- `{{SOURCE_URL}}` → 笔记的来源链接
- `{{RAW_CONTENT}}` → 原始素材内容（放在「原始素材摘录」章节）

---

## 第五步：写入正式目录

整理完成后：
1. 确定目标分类目录（如 `content/active/03-source-notes/前端工程化/`）
2. 如果分类目录不存在，创建它
3. 文件命名：`{标题}_{日期}.md`（日期用 YYYY-MM-DD 格式）
4. 将整理后的内容写入文件

**注意**：写入前先给用户预览整理结果，确认没问题再写入。

---

## 第六步：清理原始文件

用户确认整理结果 OK 之后：
- 从 `_pending/` 目录删除原始文件
- 告诉用户整理完成，包括：
  - 新文件路径
  - 内容摘要
  - 价值评分
  - 是否建议进一步升级到 `01-knowledge-base/`（如果价值很高）

---

## 工作流总览

```
_pending/原始笔记.md
    ↓ 读取
  选择模板
    ↓ AI整理
content/active/03-source-notes/{分类}/{标题}_{日期}.md
    ↓（高价值可升级）
content/active/01-knowledge-base/{分类}/{标题}.md
```

---

## 注意事项

1. **安全第一**：只整理内容，不删除任何文件直到用户明确确认
2. **保留溯源**：所有整理后的笔记都要保留「原始素材摘录」和来源链接
3. **宁欠勿滥**：不确定的内容标注「待确认」，不要编造
4. **分类灵活**：现有分类不合适就新建，不要硬塞
5. **价值筛选**：太低价值的内容（5分以下）可以建议用户直接删除，不必入库
