# vibeVibe 基础篇学习笔记

> 项目地址：https://www.vibevibe.cn/Basic/
> 记录日期：2026-07-04
> 项目类型：AI 辅助全栈开发教程（个人主页 + 数字分身）

---

## 1. 一句话总结

vibeVibe 基础篇是一套面向零基础的 AI 辅助开发教程，以「个人主页 + 数字分身」为连续案例，带领读者走完从想法生成、本地开发、内容迭代到正式上线的完整闭环，核心是教会人如何用 AI 作为执行伙伴，把想法变成可访问的真实作品。

---

## 2. 研发视角的价值判断

### 2.1 它解决了什么技术问题

这套教程解决的核心问题不是某个具体技术点，而是**「如何让非专业开发者用 AI 独立完成一个从 0 到上线的完整项目」**的方法论问题：

- **从想法到需求的转化**：用填空式模板把模糊想法变成 AI 可执行的明确需求
- **AI 协作的工作流**：如何提问、如何排错、如何迭代，而不是从零手写代码
- **最小闭环的构建**：先生成原型 → 带回本地 → 改界面 → 补内容 → 调分身 → 部署上线
- **排错思维**：报错先看日志，再交给 AI，一次只改一个变量

### 2.2 对研发的价值

| 维度 | 价值大小 | 说明 |
|------|----------|------|
| 直接拿来用 | 中 | 教程本身是学习材料，不是可直接部署的产品 |
| 架构借鉴 | 高 | 「AI 驱动的从 0 到 1 开发流程」对团队搭建 AI 辅助开发体系有参考价值 |
| AI Agent 相关 | 高 | 数字分身的人设校准、prompt 设计、排错思路可迁移到 Agent 开发 |
| 二开成本 | 低 | 教程是文档，不需要二开 |
| 实用价值总评 | 高 | 对建立 AI 辅助开发的系统化思维很有帮助 |

### 2.3 最值得借鉴的 3 个设计点

1. **连续案例教学法**：全篇围绕「个人主页 + 数字分身」同一个项目展开，每一章都在前一章基础上迭代，而不是零散的知识点堆砌。这种方式学习曲线平滑，每一步都有明确产出。
2. **填空式需求模板**：把需求拆解成「关于我 / 给谁看 / 页面要有什么 / 数字分身知道什么 / 风格要求」五个维度，大幅降低了跟 AI 沟通的门槛，本质是一种结构化 prompt 设计。
3. **最小闭环思维**：每一章都只完成一个最小闭环（生成原型 → 本地跑通 → 改一处 → 存一次 → 部署上线），而不是追求一步到位，符合 MVP 理念。

## 3. 核心架构 & 数据流

### 3.1 整体架构图

```
┌─────────────────────────────────────────────────┐
│              前端 / 交互层                        │
│  个人主页展示 + 数字分身聊天界面（HTML/CSS/JS）    │
├─────────────────────────────────────────────────┤
│              AI 对话层                            │
│  数字分身 prompt 人设 + LLM API 调用              │
├─────────────────────────────────────────────────┤
│              部署 / 基础设施层                    │
│  Git 远程仓库 + EdgeOne Pages 静态部署            │
└─────────────────────────────────────────────────┘
```

### 3.2 核心模块职责

| 模块 | 职责 | 技术实现 |
|------|------|----------|
| 个人主页 | 展示个人信息、作品、联系方式 | 静态 HTML/CSS/JS 页面 |
| 数字分身 | 回答访客问题，模拟本人语气 | LLM API + system prompt 人设设定 |
| 本地开发环境 | 代码编辑、运行、调试 | AI IDE（Trae / Cursor 等） |
| 版本控制 | 代码存档、回退 | Git（最小闭环：commit / log / reset） |
| 部署平台 | 静态页面托管、公网访问 | EdgeOne Pages（国内访问友好） |

### 3.3 关键数据流

以「访客向数字分身提问」为例：

```
访客在页面输入问题
    │
    ▼
前端聊天界面接收输入
    │
    ▼
调用 LLM API（携带 system prompt 作为人设）
    │
    ▼
LLM 生成回复
    │
    ▼
前端渲染回复内容
```

**关键设计：数字分身的「人设」怎么实现？**

- 核心是 **system prompt（数字分身说明书）**，包含：
  - 身份设定（你是谁、代表谁）
  - 知识边界（知道什么、不知道什么）
  - 语气风格（怎么说话、什么语气）
  - 回答策略（不知道的怎么说、敏感问题怎么处理）
- 不是靠训练模型，而是靠 prompt engineering 控制输出
- 校准方式：用真实材料（自我介绍、文章、问答记录）来补充上下文

## 4. Quick Start & 运行效果

### 4.1 最简启动方式

```bash
# 1. 在 AI 原型工具（秒哒等）中用模板生成 v1 原型
# 2. 导出代码到本地
# 3. 用 AI IDE（Trae）打开项目文件夹
# 4. 让 AI 判断项目类型并指导启动
# 5. 浏览器打开本地地址预览
```

### 4.2 启动后提供什么服务

- **端口号**：取决于具体项目（通常是 3000 / 5173 等）
- **Web 界面地址**：本地 localhost + 端口
- **数字分身**：页面内嵌聊天组件，调用 LLM API

### 4.3 用户视角能做什么

- 浏览个人主页（头像、介绍、作品、联系方式）
- 向数字分身提问，获取模拟本人语气的回答
- （上线后）通过公网链接分享给他人访问

## 5. 扩展性分析

### 5.1 扩展方式

| 扩展方式 | 难度 | 说明 |
|----------|------|------|
| 页面内容修改 | 低 | 改文案、加模块、调样式，用 AI 辅助即可 |
| 数字分身优化 | 中 | 调整 system prompt、补充知识库材料 |
| 后端功能接入 | 高 | 需要加服务端、数据库等（进阶篇内容） |
| 多页面 / 路由 | 中 | 从单页扩展为多页站点 |

### 5.2 推荐使用方式

这套教程更适合作为**方法论参考**，而不是拿来即用的产品：

- **如果你是零基础**：按教程一步步走，完成第一个个人主页项目，建立 AI 协作的手感
- **如果你是开发者**：重点借鉴它的「AI 辅助开发工作流」和「需求结构化方法」，可以直接套用到自己的项目里
- **如果你想做数字分身**：它的 system prompt 设计思路和校准方法很实用，可以迁移到任何对话式 AI 项目

## 6. 最简 Demo 设计

### 6.1 Demo 成本评估

- **成本判断**：低
- **判断理由**：纯前端静态页面 + LLM API 调用，不需要后端，AI 可以直接生成大部分代码

### 6.2 设计目标

- 保留：个人主页展示 + 数字分身聊天核心功能
- 去掉：复杂的动画效果、多页面路由、数据分析等

### 6.3 项目结构

```
personal-site/
├── index.html          # 主页入口
├── css/
│   └── style.css       # 样式
├── js/
│   └── chat.js         # 数字分身聊天逻辑
└── README.md
```

### 6.4 核心模块伪代码

数字分身核心逻辑：

```javascript
// 数字分身人设（system prompt）
const SYSTEM_PROMPT = `
你是【名字】的数字分身。
【一句话介绍】
你知道什么：...
你不知道什么：诚实说不知道，不要编造
你的语气：...
`;

async function sendMessage(userInput) {
  const response = await fetch(LLM_API_URL, {
    method: 'POST',
    body: JSON.stringify({
      messages: [
        { role: 'system', content: SYSTEM_PROMPT },
        { role: 'user', content: userInput }
      ]
    })
  });
  return response.json();
}
```
