# 基础篇最终产物 & 可执行步骤

***

## 一、最终产物总览

做完基础篇后，你会拿到三样东西：

| 产物    | 说明                                      |
| ----- | --------------------------------------- |
| 前端交付物 | 一个可运行的个人主页网站代码，带数字分身聊天功能                |
| 服务部署  | 静态页面托管在 EdgeOne Pages，有公网可访问链接          |
| 数字分身  | 基于 LLM API + system prompt 的对话机器人，已校准人设 |

***

## 二、可执行三步

### Step 1：准备部署平台和 API 服务

**做什么：**

1. **注册 LLM API 服务**（给数字分身用）
   - 选一个国内可访问的大模型 API 服务商
   - 拿到 API Key
   - 产出：一个可用的 API Key + API 调用地址
2. **注册代码托管平台**
   - GitHub 或 Gitee 二选一
   - 产出：一个账号 + 后续要用来存代码的远程仓库
3. **注册静态部署平台**
   - EdgeOne Pages（国内访问友好，教程推荐）
   - 产出：一个可登录的部署平台账号

**这一步做完的产出：**

- [ ] LLM API Key
- [ ] GitHub/Gitee 账号
- [ ] EdgeOne Pages 账号

***

### Step 2：用 Trae 完成项目构建

**做什么：**

1. **生成 v1 原型**
   - 用填空式模板把需求说清楚（关于我、给谁看、页面要有什么、数字分身知道什么、风格要求）
   - 把需求交给 AI 生成第一版可预览的页面
   - 产出：一个能在浏览器里打开的 v1 原型链接
2. **导出代码到本地**
   - 把生成的代码下载下来，放到固定文件夹里
   - 产出：本地项目文件夹
3. **用 Trae 打开并跑起来**
   - 用 Trae 打开项目文件夹
   - 让 Trae 判断项目类型，指导你安装依赖、启动项目
   - 产出：本地 localhost 可访问的运行页面
4. **本地迭代优化**
   - 改界面风格、补内容模块、调数字分身人设
   - 每改完一版就本地预览确认
   - 产出：逐步完善的本地项目代码
5. **Git 存档**
   - 初始化 Git，做几次 commit
   - 学会看历史、回退版本
   - 产出：带版本历史的本地仓库

**这一步做完的产出：**

- [ ] 本地可运行、可修改的完整项目代码
- [ ] 数字分身 system prompt 人设文档
- [ ] Git 仓库（含提交历史）

***

### Step 3：部署上线

**做什么：**

1. **推送到远程仓库**
   - 在 GitHub/Gitee 上创建远程仓库
   - 把本地代码 push 上去
   - 产出：远程仓库地址 + 线上代码
2. **连接部署平台**
   - 在 EdgeOne Pages 里关联刚才的远程仓库
   - 配置构建命令（让 AI 帮你判断填什么）
   - 触发第一次构建
   - 产出：部署平台的构建记录
3. **拿到公网链接**
   - 构建成功后，平台会给你一个默认域名
   - 在手机和电脑上分别打开测试
   - 产出：一个别人也能访问的公网 URL
4. **上线后自测**
   - 数字分身能不能正常聊天
   - 页面在手机上显示正不正常
   - 有没有报错
   - 产出：一份自测通过的上线版本

**这一步做完的产出：**

- [ ] 公网可访问的个人主页链接
- [ ] 数字分身功能在线可用
- [ ] 移动端适配正常

***

## 三、最终验收标准

全部做完后，用以下 checklist 验收：

| 检查项  | 标准                          |
| ---- | --------------------------- |
| 前端页面 | 公网链接能打开，展示个人信息、作品、联系方式      |
| 数字分身 | 能正常对话，回答符合人设，不会编造不知道的信息     |
| 移动端  | 手机打开显示正常，没有布局错乱             |
| 代码   | 存在远程仓库，有提交历史                |
| 部署   | EdgeOne Pages 上构建成功，有稳定访问链接 |
