## 关键设计决策

| 决策 | 原因 |
|------|------|
| **Step4 case 必须用户写，Agent 绝对不代写** | 之前营养师项目的case是用户给的，真实测出来很有用。如果Agent编case，会默认用户提问特别标准完备，真实场景一用就崩。这一条是保证产出Skill能真实落地的关键 |
| **准出规范 13 条 Checklist 做成表格，Agent自测必须全过再出手** | 之前是Agent自己心里有数，现在写死在模板里，一条条打勾，避免「我觉得差不多了」的主观判断，用户验收也直接按表查 |
| **不满意改规则不要改输出** | 之前看到用户可能会改输出文件本身，下次生成又打回原形。所有变更必须回到 PRD/plan/准出 3 个基准文件里改，Skill重新跑输出，保证可复现 |
| **把 food-skill 示例内置进 Skill references，弱化业务语义** | 用户要求 Skill 要足够独立，food-skill归档后找不到就废了。现在内置后Skill自带示例，100%自包含；所有示例文件开头加红色标注「看结构不要看营养内容」防止用户直接复制业务语义去下一个行业 |
| **每个Step都有「准出条件=必须明确收到用户的X回复才算过」** | 比如Step1必须用户说「PRD确认通过」才能进Step2，不能「先继续后面再改」— 保证PRD确实是双方确认的基准，不会后续扯皮 |
