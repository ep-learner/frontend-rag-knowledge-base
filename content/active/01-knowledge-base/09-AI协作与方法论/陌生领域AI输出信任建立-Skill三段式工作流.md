# 陌生领域 AI 输出信任建立：Skill 三段式工作流

> **分类**：AI 协作方法论 / Skill 开发 / 反幻觉
> **难度**：入门
> **更新日期**：2026-08-22

> 一句话总结：**面对完全陌生的行业，不想钻研又怕被 AI 骗 → 用「originPrd（我要什么）+ case.md（怎么测）+ plan.md（找现成高 star Skill/方案）」三段式流程，强制 AI 用「证据分级 + 验证路径 + 检索关键词」结构化输出，把可信度从「它说啥我信啥」拉到「我能每条自己查证」。**

---

## 一、核心概念：为什么要用这套流程？

### 1.1 你面对的真实问题

当你进入一个**陌生领域**（比如：营养、护肤、法律、理财、医疗常识、养宠…）时，会遇到三个无解的信息差：

| 痛点 | 后果 |
|------|------|
| **你不知道「什么是对的」** → 无法鉴别 AI 输出的对错 | 同样的问题问 3 个 AI 可能得到 3 种完全不同的答案，你不知道信谁 |
| **你不知道「效果怎么验证」** → 只能靠体感/主观感受 | 花了钱、执行了 1 个月，还是不知道到底有没有用，还是心理作用 |
| **你不知道「信息来源在哪」** → 搜索到的全是广告 | 百度/小红书/知乎搜相关关键词，前 10 页 80% 是带货/SEO/自媒体，找不到权威来源 |

**AI 的幻觉 + 信息差 = 风险极高**：你可能花了钱补错东西、做错决策、甚至伤害健康。

### 1.2 这套流程解决什么？

`originPrd + case + plan` 三段式的核心思想是：**把「相信 AI 这个人」变成「相信可被独立验证的结构」**。

不依赖「这个 AI 模型是不是够强」，而是通过以下 3 层防线，把信任从「玄学」变成「可验证」：

```
第 1 层：originPrd 把模糊需求写清楚
    ↓ 避免「我问A你答B」，避免 AI 自由发挥
第 2 层：plan.md 从 GitHub 找现成高 star Skill/方案
    ↓ 不用从零想，用社区已经验证过的 Prompt/格式约束
第 3 层：最终输出强制结构（证据分级+验证路径+检索关键词）
    ↓ 每条结论你都能自己去权威数据库搜了验证
```

最终效果：**即使你完全不懂这个领域，你也能判断「AI说的这句话可信度有多高、我要怎么自己验证它、去哪里搜才不会搜到广告」。**

### 1.3 适用场景 & 不适用

✅ **适用场景**（你不是专家、也不想成为专家，但想拿到放心的结论）：
- 个人决策类：营养补剂、护肤、养宠、健身、儿童护理
- 轻咨询类：法律常识、税务常识、保险选型基础
- 任何你不打算深入、但怕被 AI 瞎忽悠的领域

❌ **不适用场景**（必须找真人专家）：
- 临床诊断/治疗方案、法律诉讼策略、理财实盘、心理咨询 → 涉及高风险的必须持证专业人士
- 需要深度定制的方案（个性化医疗/税务筹划等）

## 二、三段式工作流详解（每一步你要给什么信息）

### 2.1 第一步：originPrd.md — 「我到底想要什么，写清楚」

**作用**：把你脑子里模糊的想法，变成结构化的需求文档。**越具体，AI 越不容易瞎发挥。**

#### originPrd 必须回答 4 个问题（缺一个就补上）：

| 要素 | 写什么 | 为什么重要 |
|------|-------|-----------|
| **① 我的背景** | 我是谁？这个领域我现在懂多少？遇到了什么具体困难？ | 防止 AI 输出「教科书级废话」，知道你是小白就不会说你听不懂的术语 |
| **② 我要解决的核心问题（≥2个）** | 列 2~5 个你最想解决的**具体问题**，用「怎么」「如何」开头，不要空话 | 防止 AI 答非所问。**有编号的问题 AI 漏答了你一眼就能看出来** |
| **③ 我对产出物的明确要求** | 格式/长度/是否要证据链/要不要验证方法/输出语气…有多少写多少 | 这是「防幻觉关键」：你要求它必须标证据等级+出处，它就不敢乱编 |
| **④ 搜索/方案范围** | 让 AI 去 GitHub 搜什么关键词？高 star 项目筛选标准？技能点要覆盖什么？ | 你不说的话 AI 就会自己随便选方案，选的可能根本不适合你 |

#### 📌 可复用 originPrd 模板（复制就能用）

```markdown
## 我的背景
（我是谁、我在这个领域有多少经验、我最近遇到了什么具体问题，越详细越好）

## 我要解决的核心问题（请一条一条回答，不要漏）
1. （我的第一个核心问题，用「怎么/如何」开头）
2. （我的第二个核心问题）
3. ……（建议 2~5 个，不要太多）

## 对最终产出物的要求
- 格式要求：（例如：必须分 4 段输出、每条建议标证据等级、必须有可执行量化指标）
- 证据要求：（例如：每一条建议必须标注来源类型，禁止编造，优先对齐中国本土指南）
- 验证要求：（例如：给出 2~3 种不靠体感的客观验证方式，有明确时间节点和检测项目）
- 避坑要求：（例如：列出常见营销骗局，明确指出什么是智商税）
- 长度要求：（例如：每个问题不超过 500 字，不要长篇大论）

## 请帮我做方案调研
去 GitHub / 开源社区搜索这个领域的高 star Skill 或 Prompt 项目，筛选标准：
- Star 数标准：（例如：≥100 star，或者 star 少但结构设计特别合理的）
- 必须满足的功能点：（例如：① 强制证据链输出 ② 有置信分级 ③ 有验证路径）
- 不想要的方案类型：（例如：纯食谱生成器、不带溯源能力的，直接排除）
请把搜索到的方案按匹配度排序，每个方案列：star 数、满足了哪些要求、缺什么、最终推荐哪个+为什么。
```

### 2.2 第二步：case.md — 「拿什么场景测，先写好」

**作用**：**在 AI 给你产出 Skill/方案之前，你先定好「测试用例」**。这样产出的方案你能立刻用真实场景验证效果，而不是等拿到手才发现「看起来很专业，但放到我身上就不会用了」。

#### case.md 的编写原则

1. **2~3 个真实、有代表性的场景**，不要编假的
2. **每个 case 必须包含**：用户画像（性别年龄基本情况）+ 具体问题（越细节越好，不要泛泛而谈）
3. **覆盖不同类型的问题**：例如 case1 是「日常亚健康调理」，case2 是「具体症状+是否需要补剂」，覆盖两类最常见的场景

#### 📌 可复用 case 模板

```markdown
## case1
用户：（性别 + 年龄 + 其他背景信息，如职业、生活习惯）
问题：（具体遇到的情况，要细节，不要说「我想健康一点」这种空话。
例：国庆暴走3万步后半月板疼，扫描没问题，医生让避免突然运动，平时没感觉，想知道是不是缺钙、要不要买补品）

## case2
用户：（另一个不同的用户画像）
问题：（另一种类型的问题，和 case1 不要重复。
例：作息饮食不规律，经常疲惫，之前没接触营养学，想通过日常饮食改善，不知道从哪下手）

## case3（可选，复杂场景）
用户：
问题：
```

### 2.3 第三步：plan.md — 「找现成的，不要从零造」

**作用**：**不要让 AI 凭空编一套新方案出来**（这样最容易幻觉），而是让它先去 GitHub / 开源社区搜「已经被很多人用过、star 高的现成 Skill/Prompt 项目」，筛选后告诉你：哪些方案好、为什么、最终推荐怎么组合。

#### plan.md 必须包含的 3 个要素

| 要素 | 内容 |
|------|------|
| **① 方案排序与对比表** | 按匹配度从高到低排 3~5 个 star 项目，每个列：star 数、满足了哪些要求、不满足什么、适用场景 |
| **② 方案选择推荐 + 理由** | 明确说「最终推荐用哪个/哪几个组合，为什么其他的不选」，不要模棱两可 |
| **③ 现成可直接用的最小版** | 如果不想装完整 Skill，直接给一个能复制粘贴的系统 Prompt 版本（融合了推荐方案的精华） |

#### 🚨 GitHub Skill 筛选的 4 个「避坑标准」（非常重要！）

很多高 star 项目「看起来 star 高，实际上完全不解决你的核心痛点」，必须按以下标准筛：

| 筛选维度 | ✅ 要选的 | ❌ 不要选的 |
|---------|---------|-----------|
| **核心能力匹配度** | 你要「证据链+防幻觉」，它必须明确写了「证据分级/引用溯源/置信标注」 | star 很高但只是「生成内容」（如食谱生成器、文案生成器），**完全不带证据校验能力的** — 这是 90% 的高星项目的通病 |
| **本土化 / 人群适配** | 有中国本土数据、对齐国内指南的优先（不然欧美结论直接套中国人有风险） | 完全基于欧美指南、没有提到中国人群差异的 |
| **输出格式约束** | 有强制结构化输出要求（分几段、每段写什么）的 | 只是说「你是一个xx专家」，没有格式约束的（这种 AI 还是会自由发挥瞎编）|
| **验证路径设计** | 主动提到「怎么验证效果、怎么二次查证」的 | 完全不说验证、只给「建议」的 |

## 三、让 AI 输出「看起来能信」的结构性设计（核心！）

前面的 originPrd/case/plan 是「输入端」的约束，**真正让输出可信，要靠「输出端」的结构强制**。这是营养师 Skill 的核心设计，你可以套用到任何陌生领域。

### 3.1 「可信任 AI 输出」的 6 段结构（任意领域通用）

不管是什么领域的 Skill，最终输出必须强制包含以下 6 段，**少一段都不行**：

| 段落 | 写什么 | 为什么能建立信任 |
|------|-------|----------------|
| **① 一句话结论** | 1~2 句话明确说「你应该做什么/先做什么/不要做什么」，禁止模棱两可 | 没有结论的 AI 输出=废话；先让用户知道「做什么」再解释 |
| **② 证据等级 + 来源** | 每条关键建议独立标注：Strong/Moderate/Low + 来源类型（指南/RCT/Meta/专家/动物实验）+ 出处机构 + 局限备注 | **这是防幻觉核心**。AI 不敢标 Strong 又写不出具体机构的 = 大概率在编 |
| **③ 可执行方案（量化）** | 每个建议具体到「多少g/多少mg/吃多久/什么时候执行」，不能说「多吃点」「适量」 | 空话谁都会说，能落地的方案才有用；量化了你就能照做，做没做到一眼知道 |
| **④ 适用边界 & 禁忌** | 明确说「适合谁/谁要小心/谁绝对不能用/和什么药冲突」 | 防止「别人适合但我不适合」造成的伤害；这是专业输出和博主带货的本质区别 |
| **⑤ 客观验证路径**（不靠体感！） | 分三级：🏠居家怎么测（2~4周）→ 🩸医院查什么项目（挂什么科、多久查）→ ⚠️体感仅参考 | **解决「怎么知道有没有效」**。有明确时间节点+检测项目=不靠主观感受 |
| **⑥ 二次查证检索关键词** | 3~5 组中英文关键词 + 权威检索源白名单（中国营养学会/知网/PubMed/Cochrane等） | **解决「我要自己确认怎么搜」**。给你关键词+告诉你去哪里搜=你能立刻验证真假 |

### 3.2 证据分级标准（任意领域通用）

三档分级，AI 必须严格对应，不能乱标：

| 等级 | 含义 | 满足条件（任意一条） |
|------|------|-------------------|
| **Strong（强证据）** | 几乎无争议，可以放心执行 | ① 权威官方指南明确推荐 ② 多篇高质量RCT+Meta分析一致结论 ③ 国家标准/法定值 |
| **Moderate（中等证据）** | 大概率有效，值得尝试，个体有差异 | ① 单项大样本RCT ② 多篇队列研究一致 ③ 行业专家共识但缺大规模人体数据 |
| **Low（低证据）** | 可能有效，不主动推荐，仅参考 | ① 仅动物/细胞实验 ② 小样本研究 ③ 观察性研究结论不一致 ④ 流行说法无严谨研究 |

**硬性规则**：
- 动物实验永远不能标 Moderate/Strong，必须标 Low + 明确警告「不能外推人体」
- 引用非本土数据必须显式标注「基于欧美人群，中国人群数据待补充」
- 绝对禁止编造期刊名/DOI/文献编号

### 3.3 检索源白名单（任意领域通用）

AI 推荐的检索源必须在白名单里，**禁止推荐百度知道/小红书/知乎/博客**：

| 领域类型 | 国内权威 | 国际权威 |
|---------|---------|---------|
| 医学/营养/健康 | 中国营养学会、中华医学会、国家卫健委、知网、万方 | PubMed、Cochrane Library、Web of Science、WHO |
| 法律 | 中国裁判文书网、最高法官网、北大法宝 | - |
| 财税 | 国家税务总局、财政部官网 | - |
| 技术/工程 | 官方文档、RFC 标准、GitHub 源码 | Stack Overflow（高票答案）、官方博客 |

### 4.2 方案选择过程（为什么选融合版？）

plan.md 筛选出了 3 个合格项目，但单个都不完美：

| 项目 | 优点 | 缺点 | 最终处理 |
|------|------|------|---------|
| personal-trainer-skill（~300 star） | 证据分级最规范、文献溯源机制最好 | 偏欧美 ISSN 运动营养、没有中国膳食指南 | ✅ 吸收它的证据分级标准（Strong/Moderate/Emerging） |
| H1an1/health-coach（~200 star） | 中文本土化、中国食物数据库、血检解读 | 证据分级粒度稍弱、没有 GRADE formal 分级 | ✅ 吸收它的本土化意识（中国 DRIs、剂量 UL 边界） |
| plan.md 第五部分现成 Prompt | 四段强制结构、简洁可落地 | 缺检索关键词模块、本土化约束不够硬 | ✅ 作为输出结构骨架，扩展到 6 段 |

最终选择：**不直接用任何一个 GitHub Skill，而是融合三者优点做成独立 Skill**。

为什么这是最优解？
- GitHub Skill 本身也是纯 Prompt 约束（没有代码逻辑），融合没有技术门槛
- 直接用欧美的会有本土适配风险，融合版可以直接强制对齐《中国居民膳食指南2022》
- 可以加入「检索关键词」这个两个 GitHub Skill 都没有、但对非专家极其重要的模块

## 五、常见误区 & 坑点

### ❌ 误区 1：star 数越高越好

**错**。star 高 = 用的人多，但**不一定解决你的核心痛点**。
- 营养师领域很多 star 1k+ 的项目，本质就是个「食谱生成器 + 卡路里计算器」，**完全没有证据分级、没有溯源、没有验证路径**，根本解决不了你「鉴别 AI 对错」的核心诉求。
- 选的时候先看「它满足不满足你的 originPrd 要求」，再看 star 数。

### ❌ 误区 2：让 AI 从零设计一套新方案最适合我

**错**。「从零设计」= 幻觉最高风险的场景。
- 陌生领域你根本不知道「正常的方案长什么样」，AI 编一套看起来很专业的东西你也辨别不出来
- **一定要先让 AI 找现成的、社区验证过的高 star 项目**，最差也要找 2~3 个项目融合着来，不要 100% 全新编

### ❌ 误区 3：写 originPrd 的时候说「给我最好的方案」就够了

**错**。你越模糊，AI 越能瞎发挥。
- 要求「最好的方案」不如要求「按这 4 个维度筛选出的前 3 个方案对比，最终推荐一个+说明为什么」
- 结构化的需求 = 结构化的产出，模糊的需求 = 瞎编的产出

### ❌ 误区 4：体感有改善 = 方案有效

**错**。安慰剂效应在营养/健康领域极强（30%+ 效果可以来自安慰剂）。
- 必须在 Skill 里强制要求「客观验证路径」：居家测什么、医院查什么、什么时间节点查
- 客观指标改善才算真的有效，体感改善只能算「可能有效，继续观察」

### ❌ 误区 5：检索的时候直接百度搜自然语言问题

**错**。前 10 页 90% 是广告。
- 必须用「组合关键词 + 权威检索源」：比如不要搜「男人疲惫吃什么」，要搜「中国居民膳食指南2022 成年男性 铁推荐摄入量」，去中国营养学会官网或者知网搜。
- 好的 Skill 会直接给你现成的组合关键词，让你复制粘贴就能搜。

### 通用方法论参考

1. **GRADE 证据分级体系** — 循证医学领域的金标准证据分级方法，本笔记的 Strong/Moderate/Low 就是简化版 GRADE
   - 检索关键词：`GRADE evidence grading system`
2. **Cochrane Handbook** — 系统综述和荟萃分析的权威操作手册，教你怎么判断研究质量
   - 官网：https://www.cochranelibrary.com
3. **PICO 框架** — 把临床/决策问题转化成可检索关键词的标准格式（Population/Intervention/Comparison/Outcome）
   - 适用场景：任何需要精确检索文献的领域
