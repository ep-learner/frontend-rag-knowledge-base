# VibeVibe 进阶篇学习笔记

> 教程地址：https://www.vibevibe.cn/Advanced/
> 记录日期：2026-07-06
> 项目类型：AI 辅助全栈开发进阶教程（16 章完整产品交付流程）

---

## 1. 一句话总结

进阶篇是一套面向有基础的学习者的**全栈产品开发实战教程**，以「从想法到上线的 100 小时」为主线，用一个完整的产品交付流程串起 16 个技术主题，核心不是教你写代码，而是教你**用 AI 作为执行伙伴，走完从需求定义、技术选型、前后端开发、测试、部署到产品迭代的完整闭环**。

---

## 2. 研发视角的价值判断

### 2.1 它解决了什么问题

进阶篇解决的不是某个具体技术点的问题，而是**「会用 AI 写代码，但做不出完整产品」**的方法论问题：

- **从 demo 到产品的跨越**：基础篇能做出静态页面，进阶篇教你做有后端、有数据库、有用户系统的完整产品
- **技术选型的判断力**：面对一堆框架和工具，知道该选什么、为什么选
- **工程化思维**：代码规范、版本控制、测试、CI/CD、部署——不是玄学，是有套路的
- **产品思维**：不是先写代码再想做什么，而是先定义问题，再用代码解决
- **全栈视角**：前端、后端、数据库、部署、运维串成一条线，不再是孤立的知识点

### 2.2 对本项目（前端 RAG 知识库）的价值

| 维度 | 价值大小 | 说明 |
|------|----------|------|
| 直接拿来用 | 中 | 部分章节（数据库、API、鉴权、部署）可直接套用到 RAG 项目 |
| 架构借鉴 | 高 | 「文档驱动开发」「AI 协作工作流」「全栈项目结构」有很强参考价值 |
| 工程化提升 | 高 | 测试、CI/CD、环境变量、安全最佳实践等能直接补全当前项目的短板 |
| 二开成本 | 低 | 教程是文档，不需要二开，按需吸收即可 |
| 实用价值总评 | 高 | 对把「玩具项目」变成「正经产品」很有帮助 |

### 2.3 最值得借鉴的 3 个设计点

1. **问题驱动的学习路径**：不是「先学 React、再学 Node、最后学数据库」的知识堆砌，而是「我要做一个产品，需要什么就学什么」的问题驱动路径。每学一个技术点，都知道它在产品里干什么用。
2. **文档驱动开发（PRD-first）**：先写需求文档，再写技术方案，最后写代码。这种看似「慢」的方式，实际上因为减少了返工，整体速度反而更快。对 AI 协作尤其重要——AI 写代码很快，但写出来的东西是不是你想要的，取决于你能不能把需求说清楚。
3. **渐进式复杂度**：从最简单的静态页面开始，一层一层加功能——加交互、加数据存储、加后端 API、加用户系统、加测试、加部署。每一步都在前一步基础上迭代，不会一下子塞太多东西让人崩溃。

进阶篇 16 章可以分成四大阶段：

```

阶段三：验证期（第 9-10 章）
```

## 5. 进阶篇核心方法论提炼

### 5.1 AI 时代的开发流程（传统 vs 进阶篇）

| 阶段 | 传统开发 | AI 辅助开发（进阶篇） |
|------|----------|---------------------|
| 需求 | 产品经理写 PRD | 你自己写 PRD，AI 帮你梳理 |
| 设计 | 设计师出设计稿 | AI 生成设计稿，你调细节 |
| 技术方案 | 架构师写技术文档 | AI 生成技术方案，你审核调整 |
| 编码 | 开发手写代码 | AI 写大部分代码，你审查修正 |
| 测试 | QA 写测试用例 | AI 写测试，你看覆盖度 |
| 部署 | 运维配置服务器 | 一键部署到 Serverless 平台 |
| 迭代 | 两周一个迭代 | 以天甚至小时为单位迭代 |

**核心变化**：流程没有消失，但每个环节的「执行」被 AI 替代了，人的角色从「执行者」变成了「决策者 + 审查者」。

### 5.2 文档驱动开发（DDD, Document-Driven Development）

进阶篇反复强调的核心理念：**先写文档，再写代码**。

为什么对 AI 协作特别重要？

- AI 写代码很快，但写出来的是不是你想要的，取决于需求说清楚了没有
- 好的文档 = 好的 prompt = 高质量的 AI 输出
- 文档还可以作为后续迭代的「锚点」——改功能之前先改文档，AI 才知道你要改什么

### 5.3 渐进式复杂度原则

不要一步到位做一个「完美的产品」，而是：

1. 先做一个**能跑的最小版本**（哪怕只有一个功能）
2. 然后**一层一层加东西**（加数据存储、加用户系统、加测试、加部署）
3. 每一步都**验证通过了再走下一步**
4. 永远保持「当前版本是可运行的」

## 6. 云 IDE（CNB）章节核心要点

### 6.1 它是什么

腾讯云 CNB（cnb.cool）上的**云原生开发环境**，本质是一个浏览器里的 VS Code，后端跑在腾讯云的容器里，预装了全套开发工具链。

### 6.2 预装了什么

- **AI 编程**：Claude Code、OpenAI Codex、Gemini Code Assist
- **运行时**：Node.js 24.x、Python 3.11+、Docker
- **开发工具**：Git、GitHub CLI、VS Code（53 个扩展）
- **运维面板**：1Panel（端口 34246）

### 6.3 适合谁用

| 人群 | 适合度 | 原因 |
|------|--------|------|
| 新手 / 零基础 | ⭐⭐⭐⭐⭐ | 不用配环境，打开就能写，降低入门门槛 |
| 电脑配置差 | ⭐⭐⭐⭐⭐ | Docker、大项目本地跑不动，云端随便造 |
| 多设备切换 | ⭐⭐⭐⭐ | 公司电脑、家里电脑、平板，环境都一样 |
| 想随时随地写 | ⭐⭐⭐⭐ | 配合 Happy Coder，手机也能操控 |
| 追求极致性能 | ⭐⭐ | 云端有网络延迟，本地还是更快 |
| 对代码隐私敏感 | ⭐⭐ | 代码在腾讯云服务器上，看信任度 |

### 6.4 注意事项

- ⚠️ **代码必须推送到 Git 仓库**，云环境闲置会自动回收，不推送就丢了
- ⚠️ 免费额度有限（1600 核时/月），重度使用可能需要付费
- ⚠️ 本质是 Linux 容器，有些 Windows 特有的东西跑不了
