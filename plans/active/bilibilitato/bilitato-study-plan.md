> 状态：计划中
> 创建日期：2026-07-12
> 项目地址：https://github.com/erikzhuang55/Bilitato
> 类型：学习项目 + 工具二开

---

## 1、背景与目标

### 1.1 背景
- B 站有大量高价值前端技术视频，人工整理笔记效率低
- BibiGPT 官方 API 已下线，纯手动流程效率受限
- Bilitato 是开源的 B站内容解析浏览器插件，可能作为本地化视频内容提取方案
- 想深入研究 B站接口协议，探索更多自动化可能性

### 1.2 目标
- **学习目的**：研究 B站视频内容提取的技术方案、接口调用协议
- **安全审查**：审计插件代码，确保无后门、无 token 泄露、数据安全可控
- **二开潜力**：评估是否可以基于此插件定制化开发，适配个人 RAG 知识库工作流
- **产出沉淀**：学习笔记 + 安全审计报告 + 定制化改造方案

---

## 2、核心关注点

### 2.1 功能探索
- 插件支持哪些 B 站内容提取（字幕/简介/评论/弹幕）
- 提取质量、准确率如何
- 是否支持批量处理
- 输出格式是否方便接入 RAG 流程

### 2.2 接口协议研究
- B站视频字幕获取方式（官方接口 / 爬取 / 其他）
- 接口调用频率限制、风控策略
- 是否有其他未公开接口可以利用
- 与现有工具（BibiGPT、豆包）的技术方案对比

### 2.3 安全审计（重中之重）
- **代码后门检查**：所有网络请求、数据上传、第三方接口调用审计
- **Token 安全**：是否会获取、上传、泄露 B站 Cookie / Token
- **权限审查**：浏览器插件申请的权限是否合理
- **数据流向**：提取的内容只在本地处理，还是会上传第三方服务器
- **依赖审计**：npm 依赖包是否有可疑项

### 2.4 二开可行性评估
- 代码质量、架构设计、可维护性
- 改造成本（是小修小补还是基本重写）
- 是否值得投入时间二开，还是直接用现成方案

## 5、风险与注意事项

1. **安全第一**：所有审计通过前，不登录 B站账号，不输入任何敏感信息
2. **合规使用**：仅供个人学习研究，遵守 B站 robots 协议，不用于商业用途
3. **频率控制**：接口调用注意频率，避免给 B站服务器造成压力
4. **预期管理**：可能研究完发现不值得二开，那就当学习了，知识沉淀下来就是收获
5. **不影响主线**：此项目为支线探索，优先级低于视频笔记主流程（豆包方案）
